# Camera coordinate seed

`camera_geo.csv` is the versioned source of truth for camera coordinates. The gateway
catalogue (`/api/ingest`) supplies **no latitude or longitude** — only a free-text
`location` string — so every coordinate in this platform originates here or from an
operator pin-drag in the Registry UI.

**Coordinates in this file are supplied by the team from a map. They are never
inferred, guessed, or generated by a geocoding service or a model.** A camera whose
position is invented is worse than a camera with no position: it produces a route
polyline that looks authoritative and is wrong, which is precisely the failure mode a
forensic reviewer is looking for.

## Columns

| Column | Meaning |
|---|---|
| `camera_ref` | `external_id` from the catalogue. Joins to `camera.external_id`. |
| `location_text` | Verbatim `location` from the catalogue, kept so a re-poll can detect renames. |
| `lat`, `lon` | WGS84 decimal degrees. Empty while `geom_source=unset`. |
| `geom_source` | `manual_survey` \| `approximate` \| `unset`. |
| `confidence_radius_m` | Positional uncertainty in metres. Drives route plausibility tolerance. |
| `resolved_by` | Who established the coordinate (person or `pin_editor:<user_id>`). |
| `resolved_at` | UTC ISO-8601 timestamp of resolution. |

## How `geom_source` and `confidence_radius_m` are used downstream

- **`unset`** — the camera is **excluded from route reconstruction entirely** and is
  surfaced in the UI as *"coordinate missing"*. It is never silently dropped: an
  operator must be able to see that a camera could have contributed evidence and
  did not, because that distinction is the difference between "the vehicle was not
  there" and "we cannot say".
- **`manual_survey`** — surveyed or map-verified. Small radius (typically ≤ 25 m).
- **`approximate`** — placed to the correct junction or building but not surveyed.
  Larger radius (typically 100–500 m).

Route reconstruction (§8.2 Stage 3) **widens its spatio-temporal tolerance in
proportion to `confidence_radius_m`** rather than treating every coordinate as exact.
Two cameras with 500 m uncertainty each can be up to 1 km further apart than their
nominal separation, so the implied-speed bound is relaxed accordingly. Without this,
approximate coordinates would generate false "impossible speed" rejections and delete
genuine hops from a real journey.

## Editing

Fill this file from a map and commit it. Corrections at runtime are made through the
admin pin-drag editor on the GIS map, which writes `geom_source=manual_survey`,
`resolved_by=pin_editor:<user_id>`, and an `audit_chain` entry recording the acting
user, the previous coordinate and the new one — so a coordinate can be corrected
without a redeploy and the correction is itself evidence.
